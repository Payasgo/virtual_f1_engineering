# F1 Engineering Academy — Architecture

## Product direction
A dark, responsive learning platform for beginners and engineering students. It combines guided lessons, interactive educational models, public motorsport data, and clearly labelled simulated data.

## Current vertical slice (v0.1)
- React + Vite frontend with responsive dark motorsport UI.
- Learning dashboard, lesson progress, engineering workspaces and challenges.
- Aerodynamics sandbox using a transparent dynamic-pressure model.
- Telemetry explorer with generated example lap channels.
- Introductory vehicle dynamics, race strategy and circuit-analysis sections.
- Explicit educational/simulation labels and model limitations.

## Target architecture
```
React + TypeScript + Vite
  ├── Learning experience (lessons, quizzes, progress)
  ├── Engineering labs (aero, telemetry, dynamics, strategy)
  ├── Visualization layer (Recharts / Three.js)
  └── API client
        |
Python FastAPI
  ├── Telemetry ingestion and normalization
  ├── Lap comparison and sector analysis
  ├── Aerodynamics / vehicle dynamics model services
  ├── Race strategy simulation
  └── Learning content and progress API
        |
PostgreSQL + file/object storage
  ├── Lesson and progress records
  ├── Dataset metadata and provenance
  └── Uploaded CSV / simulation outputs
        |
Data adapters
  ├── Public timing / telemetry sources (e.g. FastF1 where permitted)
  ├── User-provided CSV files
  ├── Generated synthetic telemetry
  └── Existing Python calculations, CAD and CFD artifacts
```

## Proposed repository structure
- `src/`: React application, components, pages, labs and visualizations.
- `api/`: FastAPI service and typed request/response models (next phase).
- `analysis/`: existing Python engineering models; add tested service wrappers.
- `data/`: documented sample datasets with units, provenance and license.
- `cad/`, `cfd/`: existing geometry and CFD workflow.
- `docs/`: architecture, data dictionary, model assumptions and developer setup.

## Data trust and provenance
Every dataset must be labelled as one of:
1. **Public** — sourced from a documented public data provider, with source, season/session, license/terms and retrieval date.
2. **User supplied** — uploaded by the learner; never silently treated as official.
3. **Simulated** — generated by this application; clearly marked and never represented as actual team telemetry.

For every channel store its name, unit, sampling interval, timestamp basis, source, and quality notes. Do not imply access to confidential team sensor streams.

## Engineering model boundaries
- Aerodynamics sandbox currently uses a steady, incompressible dynamic-pressure equation and illustrative coefficients. It is not CFD and is not a validated F1 car model.
- Telemetry sample is synthetic and illustrative. The current CSV chooser only records the selected filename; CSV parsing and validation are a follow-up task.
- Strategy and dynamics pages currently teach concepts; they are not yet predictive race or tyre models.
- CFD outputs require mesh/convergence checks, documented boundary conditions and validation before comparison.

## Development sequence
1. Establish UI and navigation (this branch).
2. Add typed telemetry CSV parser, schema validation, lap overlays and sector summaries.
3. Add public-data adapter with explicit source and license metadata.
4. Wrap and test existing vehicle-dynamics Python calculations behind FastAPI.
5. Add aerodynamic parameter studies and CFD result import/visualization.
6. Add tyre degradation, pit-stop and safety-car scenario models.
7. Add 3D car/component explorer, quizzes, persistence and accessibility polish.
